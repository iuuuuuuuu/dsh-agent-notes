# Agent Note: 锚点 slug 门禁的第三条路 —— 已知缺口，不是「不适用」

Status: proposed

Independent: 本篇不改写
[2026-10-19-three-upstream-gates-not-applicable.md](../../rejected/architecture/2026-10-19-three-upstream-gates-not-applicable.md)
的结论（不引 slug 库、不联网抓渲染结果是**对的**），只补上它当年漏掉的第三条实现路径，
并把该条从「不适用」重新定位为「已知缺口 + 重访信号」。原篇保持原样、不就地翻转，
理由翻转要另开一篇并互链 —— 这正是本篇存在的原因。

## Problem

上游 `verify-md-links.ts` 校验页内锚点（`[见上文](#注意事项)`）是否真的能跳到。本仓库
`tools/md-links.mjs` 对 `#` 开头的目标**直接跳过**（`:29-33` 的跳过规则、`:136`），
理由写在原篇：手写 slug 必须与渲染器逐字一致，否则「校验通过」不代表「点得动」。

原篇的结论是「要正确实现只有两条路」：引 slug 库、或联网抓 GitHub 渲染后的 `id`。
两条都被否掉（前者引依赖，后者要网络+浏览器），于是整条被判成**不适用**。

这个「只有两条路」说满了。

## Proposal

承认第三条路存在，并把它登记为**已知缺口**，而不是「不适用」：

> **一次性抓取真实渲染结果做固定语料，之后完全离线比对。**

它最强的地方正是当年被当成缺点的那点：不需要运行时依赖，也不需要每次联网 ——
只要**一次**抓取把 216 个标题的 slug 冻成 fixture（本仓库 `.probe/` 已有一次性探针先例），
之后就是纯本地字符串比对。正确性由「语料来自真实渲染」保证，不由「我读懂了 GitHub 的
slugify」保证。

**当前仍不实现**，理由从「不可行」降级为「成本/收益」：

- 收益侧为零 —— 本仓库实测**零处页内锚点链接**（`tools/md-links.mjs:30` 的注释即该实测），
  门禁保护的是一个当前不存在的形态；
- 成本侧是一次性语料 + 它与上游文档同步更新时的维护负担（标题一改，语料要重抓）。

因此本篇只登记两件事：**缺口在哪**、**什么时候该回来补**。

**重访信号**：一旦仓库里真的出现 `[见上文](#注意事项)` 这类页内锚点，且它断链而门禁
仍绿，就按第三条路补 fixture 门禁 —— 那时缺口已经变成了实际损失。

## Alternatives considered

**就地把原篇的「不适用」改成「已知缺口」。** 省一篇文件、读者只读一处。否掉的原因很硬：
原篇的否定对象（引依赖 / 联网抓）依然成立，改判的是**分类**而不是**证据**，两者混在一篇里，
后来人无法区分「当时否了什么」与「后来改判了什么」——本仓库
[2026-10-21-upstream-46-gates-classified-exactly-once.md](../../implemented/process/2026-10-21-upstream-46-gates-classified-exactly-once.md)
记的正是这种混淆造成的三次对账失败。

**保持原样，不登记缺口。** 最省事，且「反正现在零处使用」也说得通。否掉是因为原篇的
「只有两条路」是一句**事实错误**，留着它会让下一次有人重新论证同一个漏洞时，从一句错的
前提开始推导。

**现在就把 fixture 门禁实现掉。** 一步到位，缺口消失。否掉是因为它保护的对象当前不存在：
写一条永远不会红的门禁，会变成「门禁很多但都不咬人」的样板，而这类门禁最后一定被
`--no-verify` 绕过（本仓库
[2026-10-18-notes-coverage-gate.md](../../implemented/process/2026-10-18-notes-coverage-gate.md) 记过同一取舍）。

## Acceptance criteria

- 本仓库出现第一处页内锚点链接时，`tools/md-links.mjs` 不再静默跳过它，而是要么真的校验、
  要么明确打印「该锚点未校验」；
- 若要校验，语料来自一次真实渲染抓取（fixture 冻结在仓库里），不在门禁运行时联网；
- 有一条回归能证明：把 fixture 里某个标题改掉后，失效的锚点会让门禁变红。

## Risks

- **缺口未关闭**：现在真出现页内锚点断链，门禁仍然不会红 —— 这是明确接受的，别把它当成已解决；
- **语料腐烂**：一次性抓取的 slug 会随上游文档标题变化而过期，需在重抓时机上留信号；
- **第三条路的隐含前提**：它假设渲染器的 slug 规则在一次抓取的时间窗内稳定，规则变更时
  语料同样会失效。

## Consequences

- 收益：分类从「不适用」修正为「已知缺口」，错误前提被替换成可检验的重访信号；
  `docs/upstream-46-gates.md` 里该条的判定理由与这里对齐，不再依赖一句已证伪的「只有两条路」。
- 代价：多一篇 `proposed` 笔记要维护；且**缺口本身没有关上** —— 现在若真出现页内锚点断链，
  门禁仍然不会红。这是明确接受的代价，不是疏忽。
