# Agent Note: `docs/` 的引用没有门禁 —— 补两道，一道查链接一道查行号

Status: implemented

> 承接 [2026-10-21-upstream-46-gates-classified-exactly-once.md](2026-10-21-upstream-46-gates-classified-exactly-once.md)：
> 那一篇把 46 道判定表写进 `docs/upstream-46-gates.md`。本篇补的是
> **那张表自己的防腐** —— 判定表里全是 `文件:行号`，而它们此前不在任何门禁里。

Independent: 本篇只改引用校验的覆盖面（新增 `tools/doc-refs.mjs`、让
`tools/md-links.mjs` 把 `docs/` 纳入），不改判定内容、不改归档封印与笔记格式。

## Problem

`docs/upstream-46-gates.md` 是唯一承载 46 道「上游判据 `文件:行号` +
本地对照 `文件:行号`」的产物。它有两类引用，**两类都没人管**：

| 引用形态 | 例子 | 谁管 |
|---|---|---|
| 相对链接 | `[笔记](../.agents/notes/…)` | `tools/md-links.mjs`，但**它不扫 `docs/`** |
| 行内代码引用 | `` `lib/notes.js:625` `` | **没有任何门禁**（它不是链接，mdast 的 link 节点里看不到） |

复审（`.probe/review-final-2.md` 的 P2-6）在**同一轮**里抓出四处漂移，
全是第二类：

```
docs/upstream-46-gates.md  声称             实际
:268  README.en.md:474                    477
:268  README.md:409                       410
:189  verify-plugin.mjs:118-136 校验 __DSH_BOOT__ 信封   该名字不存在，真实位置 :161-180
:112  package.json:89 upstreamCommit      该字段已删，:89 是 "devDependencies": {
```

四处同一错法：**写了引用、被引用的东西后来动了、没人重算**。
这类错误不会自己暴露 —— 门禁不读它，测试不看它，只有人眼能发现。
而一份 46 行 × 5 个引用位的文档，人眼复查一次的成本已经高到不会有人做。

## Decision

分两道，各管一类形态，都在 `npm run check` 里。

### ① `tools/md-links.mjs` 把 `docs/` 纳入相对链接校验

`collectDocuments()` 末尾加 `walk('docs')`。零新增逻辑 —— mdast 解析、
成对括号、参考式定义这些能力已经在了，缺的只是「扫不扫这个目录」。
实测 `95 个文档、189 条相对链接全部可达`（当时 93 个；这两个数会随
`docs/` 与笔记增删而变，复核请自己跑 `node tools/md-links.mjs`）。

### ② 新增 `tools/doc-refs.mjs` 校验行内 `文件:行号`

判据只收**能机械判定的部分**。一条引用可校验，当且仅当它写在行内代码里、
形如 `path:N` / `path:N-M`，且 `path` 含 `/`（仓库相对路径，不是文件名碎片）。
可校验的必须：文件存在、`N <= M`、`M` 不超过该文件行数。

四条**有意不校验**：

- 只有文件没有行号（`` `lib/notes.js` ``）—— 存在性已由 md-links / verify-plugin 覆盖；
- 裸行号（`` `:43` ``、`` `:59-85` ``）—— 指代上文某个文件，解析它要理解段落；
- 上游语料前缀（`apps/`、`packages/`、`vendor/`、`python/`、`./`）—— 那些路径本是
  在描述**别人的**结构，本仓库不该有；
- 围栏代码块里的内容 —— 先 `blankOutFences()` 抹掉（复用 md-links 的同一实现，
  偏移量不变），示例代码里的 `path:N` 不是引用。

外部路径用**白名单 + 防腐**（`EXTERNAL_REFS`），不用前缀排除：
前缀排除会连带放过本仓库真实的 `lib/` 引用。防腐做法与
`tools/verify-plugin.mjs` 的 `RUNTIME_ARTIFACTS` 同源 —— **白名单条目自己也要被检查**。

复审 r1 指出这条只做了半套：第一版只要求「理由非空」，于是**永不命中的条目**
可以永远躺在表里，看起来像校验、实际一条都没拦过 —— 而当时那两条
（`lib/bin.js`、`.agents/notes/AGENTS.md`）正好就是这样：`docs/` 里它们只以
**文件名**出现、从不带 `:N`，所以白名单放行过 **0 条**。

现在两条都要求，缺一即红：

1. **理由非空** —— 防「先放行再想理由」；
2. **必须真的命中至少一条引用** —— 防死条目复活。

按新口径复核，两条都不合格，于是表被**清空**。表本身留着，因为它定义的是
「新增外部路径要满足什么」，而当前答案是「没有需要豁免的外部路径」。

空集合一律失败（没扫到文档 / 没扫到引用都算红），与 `tools/verify-notes.mjs` 同口径。

## Alternatives considered

- **只把 `docs/` 加进 md-links，不做行内引用门禁** —— 最小改动。**否掉因为这
  完全没盖住本轮抓到的四处漂移**：它们都是行内代码引用，不是链接。做了这条
  仍然要靠人眼，等于用「多扫了个目录」冒充「引用受管」。
- **做一个通用「所有 `文件:行号` 引用」门禁，覆盖顶层文档与全部笔记** ——
  覆盖面最大，听起来才对。**否掉因为语料极脏**：笔记正文里大量 `:43` 裸行号、
  指向上游副本的 `scripts/x.ts:83`、以及**指向 `.probe/` 探针报告**的引用
  （`.probe/` 是 gitignore 的一次性证据，任务结束就删）。
  量化过一遍（复审 r1 复核了我的第一版措辞）：`docs/` 之外含 `:N` 的行内代码
  共 **82 处**（39 处裸行号 + 43 处带路径）；按本次的严格口径（要求 `path`
  含 `/`、且不是上游前缀）只有 **1 处**真的解析不了；而按「只要形如 `path:N`
  就查」的宽口径，741 条候选里有 246 条解析不了。
  **第一版这里写的是「97 处解析不了」，那是宽口径下的一个中间数被当成了
  严格口径的结论** —— 数字没说清口径，就等于没说。
  **误报的门禁会被绕过**（`AGENTS.md` 对语义判重就是这套论证），所以宁可只查
  一个目录、查准，也不做一张两百多条误报的网。
- **用正则直接扫全文，不做围栏排除** —— 一行代码。**否掉因为示例代码里的
  `path:N` 会被当成引用**：本仓库的笔记大量引用**门禁源码片段**，那些片段里
  就有 `:行号` 字样。已经有用例守住这条（围栏里的不算引用）。
- **`split('\n').length` 当行数** —— 最自然的写法，第一版就是它。**否掉因为
  `"a\n"` 会算成 2 行**，于是 `:2` 引用一个只有 1 行的文件会被**放过**
  —— 用例「行号越界必须红」当场把这个 off-by-one 抓出来（真故障注入见 Verification）。
- **把 `docs/` 的引用校验挂进 `npm run notes:gate`** —— 复用现成入口。**否掉因为
  判据不同源**：笔记门禁验的是 `架构={lifecycle}/{class}` 与笔记格式，`docs/` 不是
  笔记树；挂进去会让「笔记门禁」这个名字开始撒谎。

## Consequences

- **收益**：`docs/` 的相对链接与 `文件:行号` 引用都受机械守护。本轮四处漂移
  里那两处 README 行号已按实测改成 `410` / `477`，另两处（`__DSH_BOOT__`、
  `package.json:89`）在本轮前已改判（一条改写成真实的 `:161-180` 信封位置、
  一条改成「字段已删除」的事实陈述），现在**再有同类漂移会被 exit 1 拦下**。
- **收益**：14 条用例（原 12 条）+ 5 次真故障注入，并且 `tools/fault-injection.mjs`
  已登记，磁盘 39 个测试文件零遗漏。新增实测事实（复审 r1 逼出来的四条）：
  - `md-links` 的 `docs/` 遍历**原先没有任何用例守**：第一条用例只断言
    `checked > 20` / `links > 30`，而笔记树自己就远超这个数 —— 把
    `walk('docs')` 整行删掉它照样绿。现在 `verifyMarkdownLinks({ root })`
    接受临时仓库根，新用例造一份「顶层 + `docs/nested/x.md` 断链」的迷你仓库，
    断言 `checked === 2` 且**恰好一处**错、且点名 `docs/nested/x.md`。
    变异验证：删 `walk('docs')` → 正好这一条红，17 条里 16 绿。
  - `EXTERNAL_REFS` 的两条死条目见 Decision②的说明，已清空表 + 加命中判定。
    变异验证：把命中判定改成恒假分支 → 「死条目」那条红。
  - 引用路径若是**名字带点的目录**（`lib/a.b`），原先 `existsSync` 过了就
    `readFileSync`，直接抛未捕获 `EISDIR` 让门禁**崩掉**（退出码非 0 但日志里
    看不出是哪篇文档写错）。现在 `statSync().isFile()` 不成立就报「引用的路径
    是目录，不是文件」。变异验证：把守卫改成恒假 → 那条用例以 `EISDIR` 红。
- **代价与已知上限**：覆盖面**只有 `docs/`**。顶层 `README.md`/`AGENTS.md` 与
  全部笔记里的行内引用**仍然没人管**，它们同样是「写了就会漂」的东西。
  重访信号：若笔记里的行内引用再次出现成批漂移，得先解决 `.probe/` 引用与
  裸行号的歧义（比如规定「引用探针报告必须用相对链接而不是行内代码」），
  再扩面 —— 直接扩会立刻产出上百条误报。
- **代价与已知上限**：行号只验「不越界」，**不验「指对了没有」**。把
  `lib/notes.js:625` 写成 `:600` 仍然绿 —— 语义正确性不可机械判定。
  这条与本仓库一贯口径一致：门禁只做能证明的那部分，剩下的靠「写理由」这类
  可验证动作促使作者真去查。
- **代价与已知上限**：命令行入口的判断不看退出码就发现不了 —— `invokedDirectly`
  写错时进程以 0 退出却**一行不输出**，门禁「通过」了但什么都没查。第一版用
  `fileURLToPath(new URL(\`file://${process.argv[1]}\`))` 拼 URL 就有这个风险
  （盘符、反斜杠、相对路径都不稳），已改成本仓库其余工具同口径的尾段比对，
  并新增一条用例断言「命令行入口真的会跑、真的打印了统计」。
- **代价与已知上限**：`EXTERNAL_REFS` 是**第二份白名单**（另一份是
  `RUNTIME_ARTIFACTS`）。两份各自防腐、互不知道；将来要加第三条时该考虑合并。
- **代价与已知上限**：`doc:refs` 让 `npm run check` 多起一个 node 进程（约 60ms），
  并让「引用一漂就红」变成常态 —— 上游语料更新后 `docs/` 里的上游行号会先红，
  那时要跟着改判据行号。**这是有意的**：门禁就该在事实变化时喊。

## Verification

```sh
node tools/md-links.mjs     # 95 个文档、189 条相对链接全部可达
node tools/doc-refs.mjs     # 1 个文档、57 条 `文件:行号` 引用全部可解析
node --test tools/doc-refs.test.mjs tools/md-links.test.mjs   # 14 + 17 条全绿
node tools/fault-injection.mjs   # 39 个测试文件全部登记，无遗漏
```

真故障注入（改生产文件 → 跑 → 还原，每次都用 `cp` 备份并核对还原后全绿）：

| 变异 | 期望 | 实际 |
|---|---|---|
| `countLines()` 末尾那行 `if (parts[last] === '') parts.pop()` 改成恒假 | 「行号越界」那条红 | ✖ 1 红（`该文件只有 2 行` 而非 1），还原后 14/14 |
| `if (!statSync(target).isFile())` → 恒假 | 「目录不是文件」那条以 `EISDIR` 红 | ✖ 1 红 + `Error: EISDIR`，还原后 14/14 |
| 死条目判定 `if (!usedExternal.has(key))` → 恒假 | 「死条目」那条红 | ✖ 1 红，还原后 14/14 |
| `md-links` 删掉 `walk('docs')` | 「docs/ 也在检查范围」那条红 | ✖ 1 红 / 16 绿，还原后 17/17 |
| `md-links` 恢复双重剥离代码区 | 「不得双重剥离」那条红 | ✖ 1 红（既有用例，前一轮做过） |

三次「修 bug 的用例」在这里都是先故障注入再算完成：一条用例如果没有
「去掉这段实现它就红」的记录，它证明的只是「我写了这行」。
