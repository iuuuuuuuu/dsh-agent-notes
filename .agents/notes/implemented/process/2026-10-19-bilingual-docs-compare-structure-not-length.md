# Agent Note: 双语文档的一致性要靠结构比，不靠字数比

Status: implemented

> 同属**完整流程补齐**这一组。
> 第三方归属声明见
> [2026-10-19-third-party-notices-are-part-of-distribution.md](./2026-10-19-third-party-notices-are-part-of-distribution.md)，
> Markdown 断链门禁见
> [2026-10-19-markdown-links-need-a-gate.md](./2026-10-19-markdown-links-need-a-gate.md)。
> 双语是本仓库的硬约束 4，但此前只门禁了「两个文件都在且带徽标」。

Independent: 本篇处理的是「两版 README 是否还讲同一件事」，与许可证披露、链接可达性是不同的失效面。

## Problem

`README.md`（中文，默认入口）与 `README.en.md`（英文）互链，`verify-plugin.mjs`
把「两个文件都在」与「都带 dsh 徽标」当门禁。但**没有任何检查确认它们还讲
同一件事**。

实测：给 `README.en.md` 追加一整节内容，中文版完全不知道，
`npm run verify` 照样绿灯（exit 0）。

这个漂移的代价是隐蔽的：英文读者看到某个功能，中文读者完全看不到，而改的
人不会察觉 —— 他只读了自己写的那一版。

### 顺带发现的真实缺口

比对过程中发现，两版 README **都**漏了 6 个使用者需要的命令：
`notes:coverage`、`notes:supersession`、`archive:note`、`doc:budget`、
`hooks:install`、`check:full`。装钩子、归档笔记这些日常操作，README 里根本没写。
这不是单边漂移，是双边遗漏 —— 但同样没有人会发现。

而 `AGENTS.md` 缺了本轮新加的 `notices` / `notices:check` / `md:links`。

## Decision

新增 `tools/bilingual-docs.mjs`：比两版的**结构**，不比字数。

`must`：比「标题层级序列 + 围栏代码块数量」，**不比对字数**。中英长度天然
不同（实测 416 行 vs 471 行，而标题数、代码块数、表格行数完全一致）。
拿字数当判据只会产出大量误报，而误报多的门禁会被绕过。

`must`：**数标题前必须剥离围栏代码块**。示例里的 `# 安装` 是 shell 注释，不是
标题。实测不剥离会让中文版的标题数从 28 掉到 25。

`must`：**双向对称检查**。只报英文侧漂移的门禁是有偏的 —— 中文版是默认入口，
中文侧单独加节同样会让英文读者看不到。

`must`：层级错位**只报第一处**。层级错位是根因，后续错位多半是它引起的连带；
报几十条会让真正的原因被淹没。

### 不做的：逐节正文语义比对

判断「这两段讲的是同一件事」要么靠语言模型，要么靠人工维护锚点映射表。后者
会变成另一件必须同步维护的东西 —— 而它漂移时同样没人发现。

结构性漂移是**可机械判定**的，正文语义漂移不是。所以只做前者。这条记在
重访信号里：若真出现「结构一致但内容讲的不是同一件事」，应引入翻译配对检查
（上游 `verify-translation-pairing` 走的就是那条路），而不是给本门禁打补丁。

### 顺带补的文档缺口

两版 README 的「自检与测试」段落补上 6 个命令与一句钩子说明（钩子可被
`--no-verify` 绕过，CI 才是权威那道）。`AGENTS.md` 补 `notices`。
README 预算因补内容从 5900 放宽到 6000（`--update` 的设计用途正是「有意放宽」）。

## Alternatives considered

- **比对两版的行数或字数** — 实现最简单，且能抓住「一版少了一大段」。否掉是因为中英长度天然不同（本仓库 416 vs 471 行，结构却完全一致），拿它当判据会长期误报。而长期误报的门禁会被绕过，等于没有。
- **比对两版的标题文字** — 那是最强的一致性保证。否掉是因为标题文字必然是两种语言，无法直接比对；要比对就得维护一张中英对照表，而那张表本身就会漂移，且漂移时没人发现。
- **比对表格行数与列表项数** — 也是结构信号。否掉是因为它们受排版影响更大：一次正常的段落拆分就会让它们变化，而那不是需要拦的漂移。收敛到「标题层级 + 代码块数」这两项最稳的信号。
- **用 mdast 做 AST 级结构比对** — 更精确，能区分更多形态。否掉是因为标题层级与围栏代码块用十几行正则就够，而 mdast 要带一棵依赖树。**这不是原则性拒绝** —— 若将来做正文语义比对，AST 是正确前提，那时该引入。
- **把双语检查塞进 `verify-plugin.mjs`** — 少一个文件、少一条 npm script。否掉是因为失败含义不同：`verify-plugin` 失败是「包装不上」，双语不一致是「文档讲的不是同一件事」。分开能让 CI 日志直接指向问题性质。
- **只补文档缺口，不加门禁** — 当前两版结构确实一致，补完就没事了。否掉是因为这正是我上一轮被纠正的判据错误：判断标准应该是「完整流程需要什么」，而不是「当前有没有问题」。改一次不动门禁，下次改的人照样不会察觉。

## Consequences

- **收益**：补齐了双语文档链上唯一没有门禁的环节。`npm run docs:bilingual` 已接入 `npm run check`。
- **收益**：10 个测试。**输入层 7/7**（单边加节、删节、层级错位、代码块数量不同各自变红；代码块注释与两版同步改动各自放行）；**实现层 8/8**（不比较标题数量/层级/代码块数、只检查英文侧、不剥离围栏、配对表为空、层级错位连环报错、`pairs` 固定为 0）。
- **收益**：实现层注入抓到 3 条**假测试**。根因全在用例构造上：
  - 「代码块里的 `#` 注释」最初是「两版各加一个含注释的代码块」—— 剥离与否都不报错（两版都多出注释标题、仍然对齐）。改成「单边加代码块」后能区分了，但代码块**数量**随之不等，报的是另一个错。最后的解法是**两版都加代码块、只在中文版写注释**。
  - 「层级错位只报一处」最初只造一处错位，删掉 `break` 也不会出现第二条错误 —— 必须造**两处**才验得到。
  这两处都和我在 md-links 上犯的是同一个错：**用「两边同时改」的用例去测单边逻辑**。
- **代价与已知上限**：只比结构，不比正文语义。结构一致但内容讲的不是同一件事，这个门禁抓不到（已记入重访信号）。
- **代价与已知上限**：标题层级序列与代码块数量是最稳的两个信号，但对「改了某段的措辞导致含义相反」这类漂移无能为力 —— 那类问题本质上是内容错误，不是同步问题。
- **代价与已知上限**：README 预算从 5900 放宽到 6000。这是**有意的取舍**，不是妥协：补的是使用者真实需要的命令说明（装钩子、归档），不是注水。余量 50，下一次补充时门禁会重新提醒。
- **重访信号**：若开始出现「结构一致但内容讲的不是同一件事」的具体案例，应引入翻译配对检查（可能是语言模型，也可能是人工维护的锚点映射表），并考虑切到 mdast 的 AST 比对。

## Verification

```sh
npm run docs:bilingual                   # 当前 1 对文件结构一致
node --test tools/bilingual-docs.test.mjs # 10 个用例
npm run gate:fault-injection             # 含「自证清单必须有真实用例」
```

故障注入（已实测）：输入层 7/7、实现层 8/8 全部符合预期。层级错位只报一条那条必须造两处错位才验得到 —— 这一点写进了测试注释，避免下一个人重蹈。
