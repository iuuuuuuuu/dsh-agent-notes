# Agent Note: Supersession 检查 —— 让「我查过既有笔记」变成可验证的动作

Status: implemented

## Problem

本仓库到 11 篇笔记时，**只有 3 篇有互链**。不是作者懒：

- `notes:gate` 的三条脚本验的是目录、格式、归档封印；
- `notes:coverage`（见 [notes-coverage-gate.md](./2026-10-18-notes-coverage-gate.md)）
  验的是「该写而没写」；
- **没有任何东西检查「新笔记与既有笔记是什么关系」。**

而笔记越多，这个缺口越致命：同一个机制可能被两篇笔记各记一次、
结论已翻转但旧篇仍是 `implemented`、部分取代没有互链导致后来人先读到过期的。

### 上游原仓库的做法

`deepseek-ai/deepseek-harness` 的 `.agents/notes/AGENTS.md` 第一句就是：

> **Every new Agent Note triggers a supersession check.**

要求写新笔记前搜索活跃笔记树，判定「完全取代 / 部分取代 / 无关」，
完全取代的必须在**同一个 PR** 里归档旧篇。它的完整规则还包括
「完整取代才可删除、删除前必须保留全部独特理由与验证缺口、修复所有入站链接」
等严格条件。

## Decision

把这些规则里**能机械化的最低要求**做成门禁：新增笔记必须满足其一。

| 路径 | 含义 |
|---|---|
| 正文里有指向既有笔记的**相对链接** | 表示它接在某个决定之后 |
| 正文声明 `Independent: <非空理由>` | 表示确实与现有决定无关 |
| 它本身在 `proposed/` 或 `rejected/` | 还没成为已落地的决定，豁免 |

**must**：只检查**新增**笔记。修改既有笔记本来就有归属，不该重走一遍流程 ——
否则每次改一行事实都要重做 supersession，人会开始用 `--no-verify`。

**must**：`Independent:` 的理由必须非空。
这一行是整个设计的关键：它把「我查过了」从**口头声明**变成
**可验证的动作** —— 写理由这件事本身会促使人真去查一遍。
理由为空则退化成「一键跳过」，与 `--no-verify` 没有区别。

## Alternatives considered

- **做语义判重（判断两篇是否讲同一个决定）** — 最贴近「真正解决重复」的目标。
  否掉：需要理解内容，做不到可靠。硬做会产出大量误报，而**误报的门禁一定会
  被绕过**（这条在 notes-coverage 的取舍里已经论证过）。一个总在误报的门禁
  比没有门禁更糟，因为它消耗的是人对门禁的信任。
- **强制每篇新笔记必须链接至少一篇既有笔记** — 判定更简单，不必读正文。
  否掉：有些笔记确实独立（比如引入一个全新方向）。没有合法出口的门禁
  会被非法出口绕过。而且 `proposed`/`rejected` 阶段本来就不该被迫挂靠。
- **把 DSH 的完整规则（完整取代才可删、删除前保留全部独特理由…）全部照搬** —
  最忠于上游。否掉：那些是**语义判断**（「独特理由是否都保留了」无法机械验证），
  只能靠人和 skill 文本约束。硬塞进门禁会变成占位式通过 —— 形式上有检查，
  实际上永远返回通过。
- **做成 SKILL.md 里的一段说明，不加门禁** — 零成本。否掉：这正是当前失效的
  那一环。skill 文本已经写得很细，问题不是不知道，而是不会主动回想。
  这条结论在 notes-coverage 里已被验证过一次。
- **要求每篇笔记在头部加 `Supersedes:` / `Superseded-by:` 结构化字段** —
  比相对链接更明确，也便于工具解析。否掉：那会改动笔记格式，而格式由
  vendored 的三个脚本校验（不能手改）。相对链接已经能表达同样的关系，
  且与上游 skill 的既有约定一致。

## Consequences

- **收益**：新笔记第一次有了「必须交代与既有决定的关系」的机械约束。
  这解决的是**长期可维护性** —— 笔记树越大，孤立笔记的代价越高。
- **收益**：`Independent:` 把「查过了」变成可审计的动作。以后翻历史能看出
  哪些笔记是明确判定过无关的，哪些是挂靠过的。
- **代价**：多一道检查，多一次 `node` 启动（实测可忽略）。
  更重要的是**多一次心智负担** —— 每次写笔记都要想「这和哪篇相关」。
  这个负担是**有意**的：它正是「防止重复记录」的代价。
- **代价**：门禁只能保证「声明了关系」，保证不了「关系判断正确」。
  有人可以随手链一篇不相关的笔记蒙过去。这是机械校验的能力边界 ——
  它能防遗忘，防不了刻意敷衍。
- **已知缺口**：不检查「旧笔记是否该被标注为已取代」。
  DSH 要求完全取代时在旧篇里注明并归档，这一步仍是语义判断，本次没做。
  重访信号：发现两篇 `implemented` 讲同一机制且结论冲突时。
- **已知缺口**：`proposed`/`rejected` 的豁免是**按路径**判的，
  不检查内容阶段是否与 `Status:` 行一致。若有人把 `implemented` 笔记放进
  `proposed/` 目录，能绕过这条检查（但会被 `notes:gate` 的 format 拦下）。

## Verification

```sh
node --test tools/notes-supersession.test.mjs   # 9 项
npm run notes:supersession                       # 查暂存区
```

五种场景实测（真实子进程 + 真实退出码）：

| 场景 | 期望 | 实测 |
|---|---|---|
| 新增笔记无链接无声明 | 红 | 1 ✅ |
| 有相对链接 | 绿 | 0 ✅ |
| `Independent:` 带理由 | 绿 | 0 ✅ |
| `Independent:` 空理由 | 红 | 1 ✅ |
| `proposed/` / `rejected/` | 豁免 | 0 ✅ |

**故障注入（三组，全部真红）**：

| 注入 | 结果 |
|---|---|
| `links.length > 0` 改成 `if (true)`（恒通过） | 3 项红 |
| 无法读取区间时 `exit 0` 代替 `exit 2` | 1 项红 |
| （第三条见下） | — |

**故障注入过程中抓到一条自己的假绿**，值得单独记：

原本还有一处 `independent !== null && independent[1].trim() !== ''` 的判断。
把它改成 `independent !== null` 后测试**仍然全绿** —— 说明那条 trim 判断
**从未被执行到**。根因：正则里的 `\S` 已经保证「冒号后至少一个非空白字符」，
`Independent:   ` 根本不匹配，`independent` 直接是 `null`。

也就是说：那条「空理由必须拒绝」的测试，**测的是正则不匹配，而不是那条判断**。
死代码 + 假绿测试同时存在。已把死代码删除，并把测试断言改成
「拒绝原因必须是『未声明』」，不再接受任何碰巧返回 1 的原因。

这条与 notes-coverage 里踩的坑同源：**故障注入必须验证「注入的确实是那个故障」**，
否则红了也不代表在测你想测的东西。
