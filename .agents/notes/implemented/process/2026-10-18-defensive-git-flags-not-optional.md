# Agent Note: 我否决了 deepseek-harness 的三个防御，其中一个是真缺陷

Status: implemented

## Problem

调研上游 `deepseek-ai/deepseek-harness` 的 `scripts/change-scope.ts` 时，
看到它给 `git diff` 挂了一串 flag，我逐条否决了其中三个，理由写的是：

> 「实测常见场景等价」「我没能构造出受影响的场景」

**这个判据是错的。** 用户反问：「他们那么多人共同协作，制定的规矩肯定有道理。」

重新逐条实测后，我推翻了全部三条：

### ① `-z` —— 真缺陷，不是防御

不带 `-z` 时 git 对非 ASCII 路径做 C 风格转义并加引号：

```text
A  "lib/\344\270\255\346\226\207.js"
```

于是 `startsWith('lib/')` **直接失败** ⇒ 中文路径的源码改动**静默放行**。

实测：一个叫 `lib/中文.js` 的文件改了代码，门禁打印
「改动未命中受管路径，无需笔记」并 `exit 0`。
反向也坏：中文文件名的笔记会被认为「没带笔记」。

这条我原本写成「不必要」，实测一跑就是**真会踩到**。

### ② `maxBuffer: 64MB`

`spawnSync` 默认 1MB。实测超限时 `status` 为 `null`，所以**不会假绿**
（会走失败分支）—— 这一点我判断对了。但它会**误报「无法判定」**，
让门禁在大仓库上不可用。这是可用性问题，不是正确性问题，仍该修。

### ③ `--no-ext-diff` / `--no-textconv` / `--no-renames` / `--ignore-submodules=none`

实测 `--name-status` 模式下 textconv 不影响文件名列表，所以这几条
确实不改变**当前**行为。但它们是防「有人特意配置过」的：
`.gitattributes` 里的 diff 驱动、`diff.renameLimit`、`submodule.ignore=all`。

**关键在判据**：「构造不出场景」不等于「不会发生」。
防御性 flag 的价值恰恰在于防那些罕见的、需要特定配置才触发的路径 ——
而这类配置一旦存在，失效方式是**静默漏检**，最难发现。

## Decision

**所有 `git diff` 调用统一带全套防御 flag**，与 DSH 的 `change-scope.ts` 对齐：

```js
git(['diff', '--no-ext-diff', '--no-textconv', '--no-renames',
     '--ignore-submodules=none', '--name-status', '-z', ...args, '--'])
```

`maxBuffer` 提到 64MB。

`must`：`-z` 的输出必须用**专用解析**读，不能 `split('\n')`。
记录格式是 `状态\0路径\0`；改名是 `R100\0旧\0新\0`，取新路径。

`must`：解析时要保住**原始路径**。中文文件名、带空格的路径在诊断输出里
必须原样出现 —— 否则人看到的报错与自己改的文件对不上。

## Alternatives considered

- **保持原判断，只修 `-z` 一条** — 最小改动。否掉：其余几条虽然当前
  不改变行为，但成本极低（只是几个字符串），而收益是防住一类
  「静默漏检」。而且它们让判定**在大仓库与改过配置的机器上可复现** ——
  可复现本身就是门禁的基本要求。
- **用 `-c core.quotepath=false` 代替 `-z`** — 一行配置就能不转义，
  比改解析简单。否掉：它依赖调用方每次都记得加 `-c`，漏一次就回到
  静默逃检；`-z` 是数据格式层面的保证，解析端不会「忘记」。
  而且路径里若真有换行，换行分隔仍会坏。
- **自己 unescape git 的 C 风格转义** — 不必改 diff 调用。否掉：
  等于重造 git 的编码逻辑（`\ooo` 八进制、`\t`、`\"`），
  实现一旦有偏差就又是静默漏检，且这类偏差很难被日常使用发现。
- **改用 `git status --porcelain -z`** — 天然带 `-z`。否掉：`status`
  描述工作区状态，无法表达 `sha^!` 这种单提交范围，
  而逐提交检查（见 [2026-10-18-notes-coverage-gate.md](2026-10-18-notes-coverage-gate.md)）依赖它。
- **在文档里记一条「注意中文路径」而不改代码** — 零成本。否掉：
  这正是《写在散文里的规矩等于没有规矩》那个结论。而且本仓库的笔记名、
  注释、文档全是中文，出现中文文件名只是时间问题。

## Consequences

- **收益**：中文/空格路径的源码改动第一次能被正确拦下。
  实测从「静默放行」变成「点名报错」。
- **收益**：判定在大仓库（`maxBuffer`）与改过 git 配置的机器上可复现。
- **收益**：确立了一条方法论 —— **不能用「我想不出场景」来否决防御性设计**。
  正确做法是问「它防的是什么、那个失效方式是否静默」。
  静默失效的防御，即使构造不出场景也该保留。
- **代价**：解析逻辑复杂了（NUL 分隔 + 状态码 + 改名双路径）。
  这份复杂度换来编码正确性，值得。
- **代价**：`maxBuffer` 64MB 意味着单次 git 输出可能占 64MB 内存。
  超了会报「无法判定」而非静默截断，方向安全。
- **已知缺口**：`-z` 解决路径编码，不解决**大小写**。
  Windows/macOS 上 `Lib/X.js` 与 `lib/x.js` 是同一文件，
  前缀判断可能漏。本次未处理（Linux CI 上不出现）。
  重访信号：Windows 开发机上出现「改了代码但门禁说没改」。
