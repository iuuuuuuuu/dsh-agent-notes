# Agent Note: npm 改名必须同步插件加载名，旧断言不能充当守卫

Status: implemented

## Problem

npm 包改名后，笔记规范开关和看板入口消失。安装补丁仍使用旧包名，而宿主将补丁的 name 当作模块 specifier 解析，不是界面显示名。客户端元数据解析失败会跳过客户端注册，因此后端工具存在并不能证明界面已加载。

本篇部分取代 [npm 包名调整笔记](2026-10-20-npm-package-rename-to-scope.md) 中关于补丁 name 不应修改的判断，其余发布归属结论不变。旧笔记已就地更正并链接本篇。

原自检把旧名写成正确答案，导致包名与加载名不一致时仍然通过。测试总数和整体绿灯没有覆盖这个跨文件契约。

## Decision

安装补丁的 name 使用当前包名 @iuuuuuuuu/agent-notes，保留树节点 id 为 agent-notes。自检从 package.json 读取包名，要求补丁恰有一个加载名且与包名相同；客户端信封 id 继续遵守同一包名契约。

新增 tools/verify-plugin.test.mjs，在临时目录复制真实包文件，运行真实自检子进程。测试覆盖绿基线，以及旧加载名、缺失加载名、重复加载名、错误包名、源码与构建产物不同步、错误信封 id、vendored 内容被改、缺失英文 README 八类故障。临时副本在 finally 中清理。

## Alternatives considered

- 保留旧加载名并增加兼容别名：可以减少旧配置迁移，但会继续依赖旧模块名可解析，掩盖安装补丁与发布包名不一致的根因。本次直接修正补丁，不增加长期别名契约。
- 只修改安装补丁：改动最小且能修正当前包，但原自检仍把旧名当正确答案，后续会阻止正确配置或再次放过错误配置。因此同步修正断言并增加真实故障注入。

## Consequences

收益是包清单、安装补丁和客户端信封的命名契约有明确守卫，旧配置不能再以自检通过的形式交付。代价是测试需要复制包文件并启动多个子进程；当前补丁只有一个插件节点，若未来扩展为多节点，需要按节点身份定位加载名，而不是放宽为任意一个名称匹配。

仓库修复不等于已发布 npm 包更新，也不等于正在运行的宿主已重新加载配置。不得把后端状态查询成功或离线测试通过写成界面恢复成功。

## Verification

新增九条真实子进程测试已执行，九条通过。构建同步故障注入必须修改 createAgentNotesClient 的函数体内部；文件尾部之外的注释不进入构建产物，不能作为有效变异。

插件包契约测试登记在 tools/fault-injection.mjs 的必备测试清单中，防止测试文件被删除后故障注入入口仍然通过。仅依赖 npm test 的通配符发现虽然维护成本更低，但文件删除后会自动缩小测试范围，不能守住这项契约，因此不采用。

补登记后，九条真实插件自检测试与 gate:fault-injection 均退出 0。在 .probe/ 内复制真实 tools/ 与 skills/，删除副本中的 tools/verify-plugin.test.mjs 后运行真实故障注入入口，断言退出码为 1 且输出明确指出该测试文件不存在；断言通过，临时副本在 finally 中清理。sync:check 同轮核对 B 的固定 ref，21 个文件相同，变更与新增均为 0；此结果不代表上游 A 的实践比对已经完成。

完整 check 链和运行中界面恢复仍需本轮收尾验证。未经明确授权不发布新版本，不为验证而重启宿主。
