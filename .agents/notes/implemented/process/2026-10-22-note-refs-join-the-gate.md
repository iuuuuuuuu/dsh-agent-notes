# Agent Note: 笔记正文的行内引用也进门禁了

Status: implemented

> 承接 [行内 `文件:行号` 引用需要门禁](./2026-10-22-inline-file-line-refs-need-a-gate.md)。
> 那篇把门禁建起来但**只扫 `docs/`**，理由是「笔记里的引用数量大、大量指向上游」。
> 这篇记录那个理由被量化推翻之后收窄执行的结论：语料扩到笔记，但排除三类不可维护的引用。

## Problem

`tools/doc-refs.mjs` 只收 `docs/`，于是 `.agents/notes/**` 里的行内引用仍然无人看。实测这一批：

```
.agents/notes/**（不含 archived/）里的行内 `path:N` 引用   14 条
其中路径在仓库里真实存在、可以机械校验                  13 条
其中解析不了                                           1 条（是笔记自己举的反例 `scripts/x.ts`）
```

也就是说 12 条**指回本仓、本来能查**的引用（`lib/notes.js:625`、`lib/board-route.js:374`、
`skills/agent-notes/assets/agent-notes-board.html:223`、`tools/verify-plugin.mjs:110-111` …）
完全靠人眼。这些正是最容易被重构悄悄改错的东西：行号一漂，引用还在、指向已经变了。

`docs/` 只有 57 条引用，笔记里另有 12 条 —— 收 `docs/` 等于把一半判定语料排除在外。

## Decision

`collectDocRefDocuments` 收 **`docs/**` + `.agents/notes/**`（跳过 `archived/`）**，
判据本身一字不改（仍是「必须存在、必须是文件、`N <= M <= 行数`」）。同时对两类引用
**结构性跳过**：

| 跳过 | 理由 |
| --- | --- |
| `.probe/` 前缀 | 探针目录被 `.gitignore` 忽略，别人的 clone 里不存在；校验它就是把门禁绑在我的本地残留上 |
| `scripts/` 前缀 | 上游 A 把全部 `verify-*.ts` 放仓库根 `scripts/`，笔记里写 `scripts/verify-*.ts:83` 说的是上游行号 |
| `archived/` 下的笔记 | 已按 SHA-256 封印，改一行就破坏清单 —— 校验它只会产出**改不动**的红 |

`archived/` 的取舍不是审美：一个**修不了的**红会让整道门禁被整体关掉，那比少查几篇更糟。
代价写在 Consequences 里。

## Alternatives considered

- **保持只扫 `docs/`** —— 最强理由是误报风险：行内引用不做语义判断，笔记正文里
  有大量「举例子」的行内引用，把例子当引用去校验就会红，而误报的门禁会被绕过。
  **否掉因为量化结果与之相反**：严格口径下 14 条候选里只有 1 条解析不了，而那 1 条
  正好是举例 —— 举例可以改成不落在校验形状里（本轮的做法是让 `scripts/` 前缀被结构性跳过），
  代价远小于「12 条判定引用永久无人看」。
- **宽口径：凡是形如 `path:N` 的行内代码都查** —— 覆盖面最大。**否掉因为语料会崩**：
  741 条候选里有 246 条解析不了，绝大多数是裸行号（`:43`、`:59-85`，指代上文某个文件）
  与上游路径。这种门禁第一天就红，然后被人加豁免加到失效。
- **给笔记单独开一张白名单，逐条标注「这是举例」** —— 听起来可控。**否掉因为白名单会变成
  默认出口**：新写一句举例就得回来加一行，加着加着就没人看理由了（同 `AGENTS.md`
  对语义判重的论证）。结构性前缀跳过是**按位置**排除，不需要为每条例外写理由，也不会随时间膨胀。
- **把 `archived/` 也纳入，红了就重新封印** —— 理论上可行。**否掉因为封印的意义就是
  「这页不再变」**：允许为改行号而重新封印，等于把只追加语义换成了「随时可改」，
  那套机制本身的保证就没了。

## Consequences

收益：

- 12 条原本无人看的判定引用进入门禁；本轮 `doc:refs` 从「1 个文档、57 条」变成
  **「92 个文档、73 条」**（含本篇自己写进去的引用），全部可解析。
- 重构改了行号却没更新笔记 → 门禁红，且报错直接给出「哪篇第几行、引用哪个文件、越界多少」。
- 收窄规则是**按位置**的，不随引用数量增长而需要维护。

代价 / 边界（必须写清，不能当成「已全部覆盖」）：

- `archived/` 那批笔记的引用仍是**死角**：如果它们指的行号漂了，门禁不会说话。
  缓解方式是本文与 `AGENTS.md` 之外没有别的 —— 这是明确接受的欠账。
- 举例型引用仍然要靠「不要写成可校验形状」自觉：本轮把 `scripts/` 整体跳过以后，
  举例恰好落在那里面；将来若有人在正文里举这种例子，门禁会红（写这篇笔记时就现场
  撞了一次），正确做法是把它放进围栏代码块 —— 围栏内不算引用，已有用例守着：

  ```
  lib/foo.js:12
  ```
- 只校验「能不能解析」，不校验「解析到的是不是那行该指的代码」。行号没越界但指向
  已经变成别的语句，门禁无感 —— 这类漂移仍需人眼，`file:line` 门禁从来只能盖住一半。

## Verification

```sh
node tools/doc-refs.mjs
# 行内引用校验通过：91 个文档、69 条 `文件:行号` 引用全部可解析。   (exit 0)

node --test tools/doc-refs.test.mjs
# tests 17 / pass 17 / fail 0                                     (exit 0)
```

新增 3 条用例：笔记里的越界引用必须红、`archived/` 不进语料、`.probe/` 引用被跳过。

真故障注入（每次只改一处、跑完按字节还原）：

| 改动 | 结果 |
| --- | --- |
| 删掉 `walk('.agents/notes')` | 16 pass / 1 fail，红的正是「笔记正文里的行内引用也要校验」 |
| 删掉 `if (name === 'archived') continue;` | 红的正是「archived/ 下的笔记被跳过」 |
| 删掉 `.probe/` 前缀过滤 | 红的正是「指向 .probe/ 的引用被跳过」 |

还原后复跑 `17/17` 绿、`doc:refs` exit 0。

已知未覆盖：`archived/` 语料；举例型引用；「行号对但内容已变」的语义漂移。
