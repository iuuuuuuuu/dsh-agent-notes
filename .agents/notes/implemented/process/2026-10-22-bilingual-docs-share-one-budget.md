# Agent Note: 双语文档成对登记并共享预算上限

Status: implemented

## Problem

本篇补充[文档预算门禁](2026-10-18-doc-budget-gate.md)，不取代其计费算法与缺文件判红决定。原清单仅登记 README.md，README.en.md 即使持续增长也不参与预算检查。双语文档地位对等，但预算覆盖不对等。

## Decision

预算门禁对磁盘上完整存在的 README.md 与 README.en.md 要求成对登记，且两份预算值相同。缺项或值不同在普通检查及 --update 中均退出 1，并明确指出问题。清单缺失、损坏或无效仍退出 2。

两份 README 均使用 6000 单位上限。沿用原 billableUnits 算法测得中文版 5999、英文版 3840，英文余量为 2160。预算相同且不压低既有中文上限，因此没有采用英文当前值加 300 至 500 的单独上限。英文余量较大是共享数值的明确代价，不代表英文可无限增长。

--update 在一份超限时同步提高配对文档预算，保证写回后仍满足相同上限。未超限时不写清单。清单中登记但文件不存在仍判红，防止删除或改名后预算静默失效；计划中文档不提前登记。

这是插件自身的开发门禁，不要求任意技术栈宿主具备 package.json、Node、npm 或安装额外宿主依赖。当前正式文档仅发现 README 这一对，新增配对文档时需扩展配对清单。

## Alternatives considered

- 为英文单独设置当前值加 300 至 500：约束更紧且余量直观；未采用，因为本次要求两份预算相同，而该值会使现有中文版立即超限。
- 只在 JSON 增加英文条目：实现最小；未采用，因为以后删掉英文条目或改成不同预算仍会静默失去对等约束。
- 只检查缺项，不检查相同预算：允许按语言分别优化上限；未采用，因为会重新允许仅对一侧设置实际有效约束。
- 缺文件当作计划中并通过：便于提前登记；未采用，因为会改变既有缺文件判红契约，并让删除或改名失去反馈。
- 在真实清单上修改后还原来测试：直接覆盖真实入口；未采用，因为并行测试会观察中间态。测试复制脚本到独立临时目录，只改夹具清单。

## Consequences

收益是双语文档都受预算保护，缺项、不同上限和自动提额后的不一致均有回归覆盖。代价是维护显式配对清单，英文获得较大余量，自动提额会同步放宽另一份文档。计费算法保持原样。
