# Agent Note: 覆盖门禁 —— 让「该写而没写」变成可机械拦截

Status: implemented

## Problem

规范写得足够细，连「对 AI 来说写在散文里的规矩等于没有规矩」都写进去了。
但在多轮对话里，**模型仍然会忘**。这不是偶发疏忽，是稳定复现的：

本仓库连续 5 次提交改了 `.github/workflows/verify.yml`，一篇笔记都没写：

```
7f8c338 ci: 用 inotify 抓 vendored 写入时刻...
d8a5606 ci: 加最小组合与 mtime 探针...
bf1ea8e ci: 逐测试文件定位 vendored 污染源
9784806 test: CI 诊断增强...
becacfc test: 拆开 CI 自检步骤并加 vendored 摘要仪表...
```

而这恰恰是规范里**明确列举**的非平凡改动类别：「改了流程与工具链」。
注意 9784806 还改了 `tools/project-skill.test.mjs` —— 属于「改了测试策略」，
同样在白名单里。

为什么漏得这么彻底？因为当时在修一个紧急的 CI 故障，注意力全在「让它绿」上，
而「这次改动要不要留笔记」需要**主动回想规范**才能想到 —— 多轮对话里
这个回想一定会被更紧迫的目标挤掉。

**既有门禁对此完全无感。** `notes:gate` 复用的是 vendored 的三条脚本：

| 门禁 | 验什么 |
|---|---|
| `tree` | 目录合法性、分类、文件名、笔记间相对链接 |
| `format` | 头块、状态、必备节、备选方案、implemented 禁用提案标题 |
| `archived` | 归档封印 |

三条全部是**「已经写了的笔记对不对」**，没有一条检查**「该写而没写」**。
笔记树为空时它们是绿的（本仓库的 `verify-notes.mjs` 外壳专门把「空集合」
判成失败，但那只是防止「一篇都没有」，对「改了代码但一篇没加」依然无效）。

所以缺的不是规范，是**从规范到执行的最后一公里**。

## Decision

新增独立的覆盖门禁 `tools/notes-coverage.mjs`，并**双层挂载**：
本地 `commit-msg` 钩子 + CI 步骤。

**① 判定口径：路径白名单，命中即要求同批带笔记。**

受管目录：`lib/`、`tools/`、`.github/`、`skills/agent-notes/`。
受管单文件：`AGENTS.md`、`CLAUDE.md`。

**must**：`AGENTS.md` 必须受管。它定义了「什么算非平凡改动」，改它就是改流程 ——
和 `.github/` 属于同一类。第一版只把 `.github/` 放进白名单、`AGENTS.md` 却没放，
实测确认改它不要求任何笔记，这是逻辑矛盾。

显式豁免（机械产物）：`tools/upstream-manifest.json`、`CHANGELOG.md`、
`package.json`、`upstream.json` 等。依据是规范里「机械改动严禁立笔记」，
为版本号/清单摘要写笔记是纯噪音。

**must**：豁免只放**生成物**，绝不放源码。第一版我误把
`tools/sync-upstream.mjs` 放进豁免表 —— 那等于给「改门禁不写笔记」
留了后门，正是本门禁要堵的洞。已删。

**must：白名单之外的新顶层目录必须显式报警。**
白名单的根本局限是**只覆盖你想到的路径**。以后引入 `apps/`、`packages/`
之类的新顶层目录时，门禁对那个目录**静默失效** —— 实测确认：退出码 0、
无任何提示。我最初把它写成「已知代价，靠人记得改清单」，但**靠人记得
正是这道门禁要治的病**，这个判定站不住。
现在改成从改动路径里抽顶层目录，凡既不在白名单也不在
`IGNORED_TOP_DIRS` 的，打一条 `⚠` 警告并说明怎么修。**不失败**（避免误报
淹没真问题），但必须出现在输出里，不再无声无息。

**② 合法出口：提交信息里 `Note-Skip: <理由>`，理由必须非空。**

**must 留出口**：路径白名单必然有误报（改个错别字、纯调注释）。
没有合法出口的门禁只会被非法出口绕过（`git commit --no-verify`），
那样连检查都跑不起来。要求理由非空，是因为「写理由」这个动作本身
就会让人再想一遍。

**③ 钩子挂 `commit-msg` 而不是 `pre-commit`。**

这是实测踩出来的：`pre-commit` 阶段本次提交信息**还不存在**，
读不到 `Note-Skip`，于是「我明明写了放行标记却被拦」。合法出口被堵死，
人就会转去 `--no-verify`，门禁等于失效。
`commit-msg` 拿得到 `$1`（`COMMIT_EDITMSG` 路径），暂存区此时也仍可查，
一个钩子同时满足两个条件。

**④ 双层而不是单层。**

实测 `git commit --no-verify` 确实能绕过本地钩子（已用真实提交验证）。
所以远端那道是权威，本地那道价值在**反馈速度**：提交前发现，
线索还热；等 CI 红回来，人已经在做别的事了。

**⑤ 无法判定时退出码 2，且 2 算失败。**

`git diff` 失败、range 解析不了 —— 这些是「查不到」，绝不能当成「没问题」。
这是假绿最经典的形态，门禁自己必须先堵住。

**⑥ 两个实现后门，都在自查中发现并修掉。**

第一版写完后我按「自己验过才认」的规矩去实测，抓到两处**能让门禁形同虚设**
的缺陷。它们比没写门禁更危险，因为看起来还在管：

- **后门 1：删除笔记被当成「带了笔记」。** 原先只判断「有没有以
  `.agents/notes/` 开头、`.md` 结尾的路径」，于是 `git rm` 一篇旧笔记
  配合任意受管改动就会被判成「同批带了笔记」而放行。
  等于**删一篇笔记就能给任意改动开门**。
  修法：`git diff --name-status --diff-filter=ACMR`，把删除（D）挡在外面，
  并用 `statusLines()` 从带状态前缀的输出里取真实路径。
- **后门 2：`Note-Skip` 从「上一次提交」继承。** 原先在拿不到本次提交信息时
  会回退去读 `git log -1 --format=%B`，于是上一条提交写过 `Note-Skip:` 之后，
  紧接着任何不相干的改动都被静默放行 —— **写一次就永久开门**。
  修法：`skipReason()` 只接受环境变量与 `--message-file` 传入的本次信息，
  彻底删掉那条回退（`lastCommitMessage` 整个移除）。

两处都补了回归测试，并做了故障注入确认会真红（见 Verification）。

**这条教训值得单拎出来**：门禁的**放行条件**和它的**拦截条件**同样需要
故障注入。我第一版的四条测试全在验「该拦的拦住了吗」，没有一条验
「放行的出口能不能被滥用」——而真实的后门恰恰在后一个方向上。

## Alternatives considered

- **只把规范再强调一遍（写进 system prompt / 每次提醒）** — 最省事，
  也最符合「加个提示就好」的直觉。否掉：这正是当前失效的那一环。
  规范本身已经写得很细了，问题不是模型不知道，而是多轮对话里
  **不会主动回想**。同一份文字再重复一遍，衰减曲线完全一样。
  提示只能降低概率，不能给出「必定被执行」的保证；而漏记笔记这件事
  一旦发生就无法事后补救 —— 当时的推理链已经凉了。
- **让模型自己判断「这次改动是否非平凡」** — 最贴合规范原意（规范本来就是
  语义判断）。否掉：这可判定的前提是理解 diff 语义，做不到可靠。
  而且它的失败方向是**漏报**（忘记判断 → 静默通过），
  正是我们要拦的那种失效。
- **不做豁免表，所有改动都要笔记** — 判定更简单，也不用维护清单。
  否掉：规范自己明令「版本打标、错别字、纯格式化严禁立笔记」，
  一个逼人写注水笔记的门禁会立刻制造噪音，而噪音让人开始用 `--no-verify`，
  最终比没有门禁更糟（因为大家以为有门禁在管）。
- **用 husky 做钩子管理** — 生态标准做法，开箱即用。否掉：本仓库硬约束是
  零运行时依赖加 vendored 内容全部可核对。为一个二十行的钩子引入
  `node_modules` 依赖与 `.husky/` 目录不值得。用 `core.hooksPath` 指向
  仓库内 `.githooks/` 即可，钩子文件本身进版本库。
- **只在 CI 拦，不装本地钩子** — 少一处实现，天然不可绕过。否掉：
  反馈太晚。这次 5 次连续漏记就是「等 CI 才发现」的典型 ——
  那时任务上下文已经切走，回头补笔记只能靠考古，写出来也是流水账。
- **只在本地钩子拦，不加 CI** — 反馈快。否掉：实测 `--no-verify`
  直接绕过，而绕过它没有任何成本也没有记录，等于门禁可以静默失效。
- **把 `Note-Skip` 允许写成空理由** — 少一层摩擦。否掉：空理由会让这个出口
  退化成「一键跳过」，跟直接 `--no-verify` 没区别，只是多一层自我安慰。

## Consequences

- **收益**：多轮对话里「忘了记」从**静默**变成**当场可见**。
  漏记笔记这件事第一次有了机械兜底，不再依赖模型当轮是否想起来。
- **收益**：判定口径是路径白名单，零歧义、可复现，不受模型状态影响。
- **收益**：`notes-coverage.mjs` 用 `process.cwd()` 而非脚本所在目录取 git 根，
  因此它本身可以拿去给别的仓库用，不是只能管本仓库。
- **代价**：白名单是**近似**。改动 `lib/` 里的一行注释也会被要求写笔记，
  即误报。缓解手段是 `Note-Skip`，但那要求人多做一步。
  误报方向是安全的（多要求，不漏要求），可接受。
- **代价**：新增一份路径清单需要维护。新增顶层目录（如 `apps/`）时
  若忘了加进 `MANAGED_PREFIXES`，门禁对那个目录**仍然静默失效** ——
  区别是这个失效现在**会被指出来**：`unclassifiedTopDirs()` 会打
  `⚠ 以下顶层目录不在受管清单里：apps` 并说明怎么修。
  代价是「看见」而不是「自动修正」，因为自动收录需要猜「哪些目录算源码」，
  误报比漏报更伤门禁威信。重访信号：CI 日志里出现这条 `⚠`。
- **代价**：本地钩子需要每个 clone 跑一次 `npm run hooks:install` 才生效。
  没跑就只剩 CI 那道（仍是权威，只是反馈慢）。这个取舍是有意的：
  自动安装（`prepare` script）会在别人 `npm install` 时偷偷改他们的
  git config，那更不礼貌。
- **已知缺口**：门禁只能检查「有没有带笔记」，**不能判断这篇笔记写得对不对**。
  实测确认：塞一个空文件到 `.agents/notes/` 能过覆盖门禁，但会被 `notes:gate`
  的 `format` 拦下（缺 `## Problem` / `## Decision` / `## Consequences`、
  缺 `Status:` 行等）。所以两道门禁是**互补**的，不需要再给覆盖门禁加
  质量校验 —— 语义质量（理由是否真实、备选是否编造）仍只能靠人，
  这是机械校验的能力边界。
- **未做**：不给历史补笔记（Owner 明确选择「只从新提交开始」）。

## Verification

```sh
npm run notes:coverage          # 检查暂存区
npm run hooks:install           # 装 commit-msg 钩子
node --test tools/notes-coverage.test.mjs   # 6 项
```

**真实提交验证**（不是只跑脚本，而是真的 `git commit`）：

| 场景 | 结果 |
|---|---|
| 改 `lib/board.js`，无笔记 | `git commit` 退出码 **1**，提交未产生 |
| 改 `lib/board.js` + `Note-Skip: 纯探针验证` | 退出码 **0**，提交成功 |
| 改 `lib/board.js` + 同批笔记 | 退出码 **0** |
| `git commit --no-verify` | 退出码 **0** —— 证明必须由 CI 兜底 |

故障注入（每组都真红，非推断）：

| 注入的缺陷 | 结果 |
|---|---|
| `isManaged()` 恒返回 `false` | 3 项红 |
| `hasNote` 恒为 `true` | 3 项红 |
| 无法判定时 `exit 0` 代替 `exit 2` | 1 项红 |
| 去掉 `--diff-filter=ACMR`（后门 1 复活） | 5 项红 |
| 把 `lastCommitMessage` 回退加回去（后门 2 复活） | 1 项红 |
| `AGENTS.md` 移出 `MANAGED_FILES` | 1 项红 |
| 去掉未归类目录警告（`stray = []`） | 1 项红 |

七组覆盖了门禁的拦截分支、放行分支与覆盖面边界，证明它不是恒绿。

**注意第 4、5 组的第一次尝试是无效注入**：我最初用 `require()` 在 ESM 里
造故障，脚本直接崩溃而不是「静默放行」，测试红了但红的理由不对。
改成正确复现原缺陷（恢复回退逻辑）后才拿到可信结论 ——
故障注入本身也必须验证「注入的确实是那个故障」。

CI 侧：`verify` job 新增「笔记覆盖门禁」步骤，用
`github.event.before`（push）或 `pull_request.base.sha`（PR）作 base，
并给 `actions/checkout` 加 `fetch-depth: 0`（默认 depth 1 拿不到 base，
门禁会退化成退出码 2）。
