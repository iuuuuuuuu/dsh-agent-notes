# Agent Note: 看板同时识别项目技能和已有决策笔记，并持续跟随当前主会话

Status: implemented

> 空文档不能仅凭 iframe 的 load 判成功，恢复及桌面白屏处理见
> [空 iframe 恢复](2026-11-20-board-recovers-empty-iframe.md)。本篇接入判据与 cwd 规则保持。

## Problem

用户报告：工作区已经有决策笔记与 `notes-scripts` 配套，却没有「笔记」tab。
复现时已有 427 篇独立笔记，但没有项目级 skill 副本，`/status` 返回 `available:false`。

上一版为解决「无关项目也出现 tab」，把条件收紧为仅识别技能目录，混淆了两个问题：
空目录不足以证明接入，不代表已经有真实笔记的项目必须另外安装一份 skill。
另一个缺口是客户端只在挂载时查询；同会话初始化首篇、或第一次请求碰上路由未就绪后，
磁盘变化不会再触发判定。

## Decision

### 可见性依据是真实内容或已安装的技能

`projectUsesNotes` 只接受明确的绝对工作目录。支持两个独立入口：

- `agent-notes` 或 `write-notes-like-deepseek` 的 `SKILL.md`，且头部 `name` 对应上述身份；
  检查项目 `.agents/skills`、`.claude/skills` 及插件自身的 `skills/agent-notes` 布局。
  空技能目录与名字碰巧含 `notes` 的其他技能不算。
- 看板实际读取的笔记根中至少有一篇独立决策笔记：标准生命周期/分类、日期文件名、
  `Agent Note` 标题；翻译旁挂不算。可见性不是格式门禁，不要求全树合规才允许查看。

根目录使用既有 `findRepoRoot`；笔记根解析器由插件入口传入，与 `/board` 的配置覆盖和
工作树合并保持一致。技能命中就返回，不预先调用 Git。笔记检测复用看板枚举器，
找到首篇即停止，避免每次状态查询读取数百篇正文。`scanNotes` 原有排序及数据形状保留。

### 主会话持续查询，旧请求失效

无渲染闸门继续驻留输入区，首次查询后每 4 秒串行复查；前一次结束才排下一次，
组件清理时停表。首次创建笔记后不需要重载，暂时的 HTTP 故障也有重试机会。

cwd 可从宿主 `useSessions` 精确读取本会话条目，状态查询与看板 iframe 都携带它。
真实打开看板时发现：旧会话在服务端没有可用 header，仅修复 tab 判据会显示 tab 却回 409；
因此 iframe 也必须沿用同一回退来源。服务端仍优先采用已知会话的 cwd。
宿主提供 `useSessionRetainInfo` 时，只有 `mainView` 持有的会话能驱动全局 tab，
嵌入的子会话不会把主会话看板关掉。旧宿主缺该能力时保留原先的槽位行为。

会话或 cwd 改变时先收起旧 tab；同一目标重挂载不闪烁。请求带代次检查，
已卸载或被新会话取代的响应既不改变 tab，也不再排下一轮。
网络错误不等同于可用或不可用，只保留同一目标上次的结果。

  **部分取代**仅认技能、只查一次的规则；默认启用、删除按钮、无关项目不显示保持。
  老记录保留原理由并互链，不把旧决定改成反面。
- [注册结果记账](2026-10-19-registration-state-must-record-results.md)：
  **部分重叠**；继续按 disposer 表示实际注册结果，不改其失败可重试语义。

  **部分重叠**；复用根解析器现有短缓存，不新增永久缓存、不缓存可见性结果。

  **无关的机制**；那篇针对 iframe 全量数据，不能依靠 iframe 的可见性发现尚未出现的 tab。
  本次只对当前主会话查询小型布尔状态，不更改数据轮询。

## Alternatives considered

- **只识别 skill**：最容易避免空目录误报，但会隐藏已使用全局技能或旧式脚本配套的真实项目，
  正是这次复现；不采用。
- **只要 `.agents/notes` 存在就显示**：简单且能覆盖旧项目，但会让空壳目录再次触发空 tab；
  改为验证首篇内容，而不是恢复目录存在判据。
- **仅在挂载时查询**：没有定时请求开销，但磁盘创建首篇不会触发 React 依赖变化，
  一次启动失败也永久不恢复；采用串行短轮询，不增加文件监视器和推送协议。

## Consequences

- 已有笔记但没有项目级技能副本的工作区可直接查看，无须修改该工作区或复制技能。
- 空笔记树、空技能壳、无关 Markdown 和其他 notes 技能仍不触发 tab。
- 每个当前主会话增加一次约 4 秒间隔的状态请求；不读取所有正文，技能路径命中不探 Git。
  请求耗时会累加到间隔，弱网下不能承诺精确 4 秒显示。
- 宿主若新增每会话条件视图 API，可以去掉全局注册的代次协调；当前仍依赖常驻槽位。
- 支持技能位置限于上述已知布局；非标准布局已有真实笔记时仍可展示，其他布局可按证据扩展。
