# Agent Note: 「取不到语料」被报成「校验失败」—— eol 门禁的退出码通道

Status: implemented

> 本篇只改**退出码通道**，判据一个字没动。语料口径（不设开关、拒绝改用工作区遍历）
> 由[取不到语料就必须红](2026-10-23-corpus-substitution-must-fail-closed.md)定下；
> 退出码 2 的含义由[断网时门禁报「契约被破坏」](2026-10-19-network-down-reported-as-contract-broken.md)定下。
> 本篇补的是那两篇之间剩下的缝：语料取不到时，**判红的方向已经对了，通道还是错的**。

## Problem

审计报告 `.probe/audit-tool-gates.md` 的「发现 5」用真实执行抓到这条，实测命令与输出：

```console
$ PATH="" node tools/eol.mjs
结尾换行校验失败：1 处
  ✖ 取不到已跟踪文件列表（git ls-files 失败）：spawnSync git ENOENT —— 拒绝改用工作区遍历，因为那会换掉语料并让这道门禁看起来仍然通过
$ echo $?
1
```

**文案是诚实的，通道是错的。** 本仓库的约定是：

| 退出码 | 含义 |
|---|---|
| `0` | 通过 |
| `1` | **检查失败** —— 这批文件真的违反了规则 |
| `2` | **无法进行** —— 环境不可用，本次没验成 |

上面那次运行里 `git` 根本不在 `PATH` 上，`listTrackedFiles()` 连语料都没取到
（`source: 'git-error'`，`checked: 0`），一条文件都没看过 —— 那是「无法进行」，
不是「这批文件违反了结尾换行规则」。

调用方（CI、`npm run check` 链、读日志的人）只看得见退出码：读到 1 就会去查
「哪几个文件的结尾换行坏了」，而真因是环境里没有 git。**误导排查方向正是这条缺陷
的代价**，与[断网那次](2026-10-19-network-down-reported-as-contract-broken.md)是同一类病：
信息说的不是事实，只是这次错在退出码而不是措辞。

根因（文件:行号）：

- `tools/eol.mjs:149-155` 的 catch 已经**正确区分**了「不是 git 仓库」（合法回退信号）
  与其它任何失败（`git-error`）—— 这一层比 `verify-notes` 做得好，是该保留的；
- `tools/eol.mjs:194-210`（改动前行号）把 `git-error` 与 `git-empty` 都塞进 `errors[]`；
- `tools/eol.mjs:243-247`（改动前行号）的 `main()` 只按 `errors.length > 0` 判红，
  一律 `process.exit(1)` —— 于是「无法进行」被压进了「检查失败」这个通道。

## Decision

`verifyTrailingNewlines()` 的返回值多一个 `exitCode` 字段，**按类别算**
（`tools/syntax-check.mjs:57` 的 `unknown ? 2 : errors.length > 0 ? 1 : 0` 是同款写法）：

| 情形 | `source` | `exitCode` |
|---|---|---|
| 扫完且无违规 | `git` / `fs` | `0` |
| 扫完且有违规 | `git` / `fs` | `1` |
| 索引为空（真语料异常） | `git-empty` | `1` |
| 语料取不到（git 失败/不可用） | `git-error` | **`2`** |

`main()` 只按 `result.exitCode` 分流（`tools/eol.mjs:256-262` 是 exit 2 分支，
`:263-275` 是 0 与 1 两个分支），不再用 `errors.length > 0` 代替退出码。

### must：只有 `git-error` 走 2，其它一律 1

`must`：**不许把 exit 1 的情形一起放宽成 2。** 真违规、`git-empty` 都留在 1：
前者是「该修文件」，后者是「索引里一个文件都没有」的真语料异常 —— 两者都
**确实扫过语料**，都给出了结论。若一刀切成 2，CI 就再也分不清「改文件」和
「环境不行」，那和现在分不清「环境不行」和「改文件」是同一个错误的反面。

### must：判据本身不动，降级口子不关

`must`：**判据、`git-error`/`git-empty` 的区分、以及「拒绝改用工作区遍历」的设计
一个字都不改**（`tools/eol.mjs:124-133` 解释了为什么不给调用方开关）。
唯一新增的回退口子仍是那条：git 明确报 `not a git repository`
（`tools/eol.mjs:151`）才退回文件系统遍历 —— 那是可判定的、只有夹具才有的状态。

### must：exit 2 的分支不许说「校验失败」

`must`：exit 2 分支只说「无法进行」与「本次没有完成校验」（`tools/eol.mjs:257`），
**不打印**「结尾换行校验失败」，也不解释「缺结尾换行会让 diff 出现
`\ No newline at end of file`」—— 那是违规的后果，而这次一条文件都没检查。
解释后果的文字只留在 exit 1 分支里。

### 现有诚实诊断文案原样保留

`取不到已跟踪文件列表（git ls-files 失败）：… —— 拒绝改用工作区遍历，因为那会换掉语料
并让这道门禁看起来仍然通过` 这条**逐字保留**（`tools/eol.mjs:214-215`）。
它本来就是对的，缺的只是一句「本次没有完成校验」。

## Alternatives considered

- **① 把所有 `errors` 一律压成 exit 2。** 这是本篇**最强的被否方案**：改动最小
  （一行，`process.exit(2)`），而且方向听上去更保守 —— 「报错就退 2，不让调用方
  误判成文件违规」。否掉的原因很硬：真违规会失去可区分的退出码。CI 上一条真违规
  一旦退 2，会被读成「环境不行，重跑一次就好」，**该修的文件就没人修了** ——
  把「误报成结论」换成「真结论被当成环境问题」，是同一个病的另一半。
  用例 `eol: 真违规文件时 CLI 仍然退 1` 就是为这条备选钉的。
- **② 在输出里加一个特殊前缀（如 `EOL-UNAVAILABLE:`），让调用方自己认。**
  不动退出码、零语义风险。否掉因为**调用方读的是退出码**：本仓库 `AGENTS.md`
  的硬约束 2 就是「门禁以退出码为准」，`tools/fault-injection.mjs:261-265` 更是
  专门把「子进程没正常结束」从「变红」里挑出来 —— 这套体系里没有「靠解析文本判断
  该不该重试」的先例，加一条就是给自己造第二个真相来源。
- **③ guard 里让 git 缺失也退回工作区遍历**（把 ENOENT 当成「不是仓库」）。
  这是[已否决过的老路](2026-10-23-corpus-substitution-must-fail-closed.md)：
  换一份语料继续报「通过」是假绿，不是降级。这里提它是因为「反正没检查成，
  不如扫一下」在修退出码时很容易被顺手写出来。
- **④ 只改文案不改退出码**（把「校验失败」换成「无法进行」，保持 exit 1）。
  成本最低、输出立刻变诚实。否掉因为**机器读不到文案**：CI 与 `npm run check`
  链看退出码，一个措辞正确但退出码为 1 的门禁仍然会被当成「这批文件违规」，
  只是人读日志时才发现被骗。这与[断网那篇](2026-10-19-network-down-reported-as-contract-broken.md)
  的结论一致：两类失败必须走两条通道。
- **⑤ 把 `exitCode` 只加在 `main()` 里（读 `result.source` 判断），不动返回值。**
  改动面更小。否掉因为「按类别算退出码」这条判据就藏进了 CLI 里，测试只能靠
  真起子进程才验得到类别映射；放进返回值后，类别可以被单测直接断言
  （`eol: 真仓库里 git 坏了必须失败关闭` 里那行 `assert.equal(result.exitCode, 2)`），
  与 `syntax-check.mjs` 的形态也一致。

## Consequences

收益：

- 退出码开始说真话：`git-error` ⇒ 2，调用方可以据此判断「该不该重试」；
  真违规仍是 1，CI 上的可区分性没有丢。
- 全仓库退出码口径一致 —— 审计逐个核过 `syntax-check` / `doc-budget` /
  `notes-coverage` / `notes-supersession` / `verify-notes` / `live-evidence` /
  `install-hooks` 都是 0/1/2 三态，`eol` 曾是唯一例外。
- 类别映射放进了返回值，因此可以被**单测直接断言**，不必只靠起子进程。

代价与已知上限：

- **上限一：CI 分不清「git 不可用」的两种子类。** 装了 git 但索引损坏、以及
  git 完全不在 `PATH` 上，都落 `git-error` ⇒ 2，退出码上看不出区别（文案里看得出）。
  这条是**有意**的：两者都是「语料取不到」，都该由人看一眼环境。
- **上限二：新用例依赖 `PATH` 被清空这一点。** 夹具里用 `env: { PATH: '' }` +
  绝对路径的 `process.execPath` 来制造「找不到 git」。本机实测子进程能正常起来、
  `spawnSync git` 得到 ENOENT；但若将来 CI 的 node 需要 `PATH` 才能启动，
  这条会以**测试自身报错**的形式失效（不是静默变绿）。所以同时补了一条不依赖
  `PATH` 的路径（写坏 `.git/index` 的真故障）——两条独立触发同一条通道。
- **上限三：`exitCode` 是新增字段，`assert.equal` 在字段缺失时靠 `undefined !== 2` 判红。**
  也就是说「字段被删掉」会失败在能失败的一侧，可接受；但若有人把它改成字符串
  `'2'`，严格相等会红 —— 这正是想要的。
- **上限四：`main()` 现在是三条分支，输出文案分两套。** 代价是「违规解释」与
  「环境解释」各写一遍；收益是 exit 2 时**不会**混进「这批文件违规」的话术。
  用例 `eol: git 不可用时 CLI 退 2` 明确断言输出里**不含**「校验失败」与文件名。
- 重访信号：若将来 `git ls-files` 增加了「语料部分可用」的中间态（例如
  `--error-unmatch` 之类的新语义），需要重新划这条线；届时改的是
  `tools/eol.mjs:208-218` 的分类，别再动 `main()` 的分流形状。

```console
$ PATH="" node tools/eol.mjs
结尾换行校验无法进行：1 处 —— 本次没有完成校验，一条文件都没检查
  ✖ 取不到已跟踪文件列表（git ls-files 失败）：spawnSync git ENOENT —— 拒绝改用工作区遍历，因为那会换掉语料并让这道门禁看起来仍然通过
  退出码 2 = 无法进行（环境不可用），不是「这批文件违反了结尾换行规则」。
  语料取不到时不许换一份语料继续报通过 —— 所以这里既不改用工作区遍历，也不下失败结论。
$ echo $?

```

新增用例（`tools/eol.test.mjs:276-295`、`:297-313`、`:315-330`、`:332-349`）都在**真子进程**里
跑被复制进夹具的**真脚本本体**（`copyToolInto()`，`tools/eol.test.mjs:79-94`），
断言的是调用方真正读到的那个数：

- `eol: git 不可用时 CLI 退 2`：夹具里放一个真违规文件（缺结尾换行），
  `PATH` 清空 ⇒ exit 2，输出含「无法进行 / 没有完成校验」，**不含**「校验失败」、
  **不含** `bad.md`、**不含** `No newline at end of file`（没检查成就没有文件级结论）；
- `eol: 真仓库里 git 坏了时 CLI 也退 2`：真 `git init` + 真提交后写坏 `.git/index`
  ⇒ exit 2，诊断含「取不到已跟踪文件列表」；
- `eol: 真违规文件时 CLI 仍然退 1`：真违规（结尾多空行）⇒ exit 1，输出含
  「校验失败」与文件名，**不含**「无法进行」；
- `eol: CLI 在「不是 git 仓库」时仍退回文件系统遍历并退 1`：普通临时目录 ⇒
  fs 遍历、exit 1、报出文件名、**不含**「取不到已跟踪文件列表」——
  钉住「合法回退信号不是错误」。

真变异（逐字还原，还原后 `sha256sum tools/eol.mjs` 与变异前一致）：

1. `git-error` 分支的 `exitCode: 2` 改回 `1`（即恢复被修的缺陷）⇒
   **14 pass / 3 fail**，红的正是三条判「取不到语料 ⇒ 2」的用例：
   `真仓库里 git 坏了必须失败关闭`、`git 不可用时 CLI 退 2`、`真仓库里 git 坏了时 CLI 也退 2`；
   两条 exit-1 用例保持绿 —— 证明判据不是「一律退 2」。
2. 保留 `exitCode: 2`，只把 exit 2 分支的首行文案换成「结尾换行校验失败：N 处」⇒
   **16 pass / 1 fail**（`git 不可用时 CLI 退 2`，断言「必须明说本次没有完成校验」）。
   说明「不许说成校验失败」这条不是文案洁癖，有用例钉住。
