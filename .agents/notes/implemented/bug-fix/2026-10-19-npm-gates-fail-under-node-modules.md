# Agent Note: npm 包在 node_modules 下门禁跑不起来 —— 修法与一次假象

Status: implemented

> 与 [2026-10-19-archive-breaks-relative-links.md](../bug-fix/2026-10-19-archive-breaks-relative-links.md)
> 同一类问题：**本地永远测不出来的那种**。
> 那篇是「内容被封印后改不了」，本篇是「本地跑得好好的、装成包就坏」。
> 门禁 `prepareScriptForExecution` 是本篇的主体。

Independent: 那篇讲归档断链的改写顺序，本篇讲 npm 发布路径；两者只在
「自动改写型工具必须覆盖参考式」这条原则上同源，改动不重叠。

## Problem

发 npm 包时实测到一个**本地永远看不到**的失效：

```
node node_modules/probe/a.ts
→ ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING
```

加 `--experimental-strip-types` **也拦不住** —— 限制在路径本身，不在开关。

而 `skills/agent-notes/scripts/` 下 **7 个门禁脚本全是 `.ts`**。
所以**直接发包 = 交付一个装完就坏的门禁**。

★ 关键在于**本地测不出来**：本地仓库不在 `node_modules` 下，
跑 `node skills/agent-notes/scripts/verify-agent-note-tree.ts` 一切正常。
`npm run check` 340/340 全绿，**对这个问题完全无感**。

## Decision

**运行时把 scripts 目录复制到临时位置再执行** —— 零转译。

理由三条：

1. **零转译风险**。那 7 个文件用了 52 处 TS 语法，正则/扫描器转译我实测栽了三次（见下）。
2. **天然免疫上游同步**。`skills/` 是 vendored 会随上游更新，预编译就要记得重新编译 —— 那本身是一类新的漏。
3. Node 的剥除器**只对路径有要求，对语法没有**。复制到 `tempdir` 就满足。

配套两条纪律：
- **复制整个目录**（脚本之间互相 `import`），不是单个文件。
- 临时目录要写 `{"type":"module"}`，否则每次执行打 `MODULE_TYPELESS_PACKAGE_JSON` 警告污染门禁输出。

## ★ 三次失败的转译尝试（被否的那条路）

有人（另一个执行体）写了正则转译器 + 预编译产物目录。我接着修了三轮：

| 轮次 | 做法 | 结果 |
|---|---|---|
| ① | 正则剥类型 | 4/7 通过，漏 4 类语法 |
| ② | 补上那 4 类 | 3/7 通过，仍漏 3 类 |
| ③ | 换成配平扫描器 | **0/7** —— 误吞括号，把函数调用的实参当成函数声明的参数列表 |

第 ③ 次的教训最值钱：**同一个方法连栽两次就该换方法，不是再调参数。**

★ 我随后改用 Node 官方的 `module.stripTypeScriptTypes`，**7/7 一次过**（实测那 5 个
难例零残留）。**但仍不采用预编译** —— 上面的理由 2 成立：预编译产物要跟着
上游同步重新生成，那是一条新的漏。

★ 也就是说：官方 API 能做，**但那是「能不能做」的问题，不是「该不该做」**。

### 那一处语法校验错误（独立缺陷，叠在一起才漏过去）

原校验用 `new Function(js)` —— 它造的是 **CommonJS 函数体**，于是每个 ESM
文件都抛「Cannot use import statement outside a module」，**7/7 全误报**。

结果那些坏产物**一个都没被拦住**。

★ 两处独立缺陷（转译不全 + 校验误报）叠在一起，才让坏产物通过。
  单修任何一处都拦不住 —— 这与「测试工具自己坏了」那几次同源。

现改用 `node --check` + 临时 `.mjs`，**与产物最终的加载方式一致**。

## ★★ 真正的根因：一个退格符

修完语法问题后，真机验证仍然失败：函数返回**原路径**，没复制。

`cat -A` 显示第 451 行：

```
if (!/^Hnode_modules^H/i.test(script)) return { script, cleanup: noop };
                    ^^ 退格符（0x08）
```

语义变成 `/\x08node_modules\x08/` —— **永不匹配**。
于是对任何路径都直接返回原路径，**这个函数一直没生效**。

★ **`tools/text-integrity.mjs` 本来抓得到**（它报「第 451 行含裸控制字符」）。
  我是在 `npm run check` 之后才引入这些改动，所以没赶上 ——
  **但这说明门禁是对的，是我没在改动后立刻跑**。

★ 而这行若不是**真机验证**（把包装进 node_modules 真跑），永远看不出来：
  本地走的是「不复制」的**正确分支**，看起来一切正常。

## Alternatives considered

- **预编译成 `.js` 放进包** —— 直接解决 node_modules 限制。**这是本篇最强的一条被否方案**，理由是「预编译产物要跟着 vendored 上游同步重新生成，那是一条新的漏」。而且我实测手写转译在该任务上连栽三次。★ 官方 API 确实能做（7/7 过），**但那是「能不能」，不是「该不该」**。
- **改 `skills/` 下的 `.ts` 为 `.js`** —— 一劳永逸。**否掉因为那是 vendored 上游内容**，手改会被 `verify-plugin.mjs` 的 SHA-256 比对拦下。
- **发包时不含那 7 个脚本** —— 简单。**否掉因为插件的用户会用到门禁**（`agent_notes_gate` 工具要跑它们），缺了就是功能缺失。
- **只在 README 里说明「门禁在 npm 包里不可用」** —— 零成本。**否掉因为那是把「我做不到」写成「使用者该知道」**。这里做不到的原因是可修的。

## Consequences

- **收益**：npm 包在 `node_modules` 下门禁**真能跑通**（实测 exit=0，输出 `ok: 67 note(s)`）。三个脚本逐一验过。
- **收益**：零转译、零预编译产物、**免疫上游同步**。
- **代价与已知上限**：每次执行门禁要**复制一次目录**（7 个小文件，约几十 KB）。这是磁盘 IO，不是启动阻塞 —— 但若门禁被高频调用，开销会累积。当前是「用户手动触发」，可接受。
- **代价与已知上限**：临时目录用 `mkdtempSync` 且 `cleanup` 由调用方负责。若调用方漏调，临时文件会残留。**当前三个调用点都调了，但那是纪律不是机制**。
- **代价与已知上限**：降级路径（`readdirSync` 失败 → 按原路径执行）在 `node_modules` 下必然失败。**所以降级不是「更差的成功」，而是「明确的失败」** —— 靠 `warnDegraded` 写 stderr 留痕。这符合本仓库「静默降级会让『看起来正常其实没生效』成为常态」的判断。
- **重访信号**：
  - **上游把那 7 个脚本改成 `.js`** → 整个复制机制可以去掉，`prepareScriptForExecution` 退化成 no-op。
  - **Node 支持在 `node_modules` 下剥离类型**（如 `ERR_` 那个限制被解除）→ 同样可以去掉。
  - **门禁改成高频调用** → 每次复制目录的开销需要重新评估，那时该考虑官方 API 预编译 + 同步时自动重编译。

### 一条方法教训

**本地测试对「路径/环境类失效」完全无感。** 这类问题只有一个验法：
把产物装进**那个真实环境**里跑。

本篇若只跑 `npm run check`，退格符那一处会一路带到 npm 上 ——
340 项全绿，而交付出去的门禁**一个都跑不起来**。
