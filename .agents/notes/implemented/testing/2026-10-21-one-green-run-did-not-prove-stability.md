# Agent Note: 一次全绿没有证明测试是稳的 —— 子进程崩溃被当成「非零退出」

Status: implemented

> 独立观察，不取代任何既有决定；与
> [故障注入清单必须与磁盘对账](../process/2026-10-21-fault-injection-list-must-reconcile-with-disk.md)
> 的「自证不是覆盖率」是同一条纪律的另一面：**一次绿也不是稳定性**。

## Problem

`npm run check` 串了 14 道门禁 + 424 条测试。2026-10-21 的一次全量运行里，
`tools/archive-note.test.mjs` 的用例「archive:note: 缺参数时非零退出」失败：

```
✖ archive:note: 缺参数时非零退出 (3016.6428ms)
  AssertionError [ERR_ASSERTION]: 缺参数必须 exit 1，实际 3221226505
```

`3221226505` 是 `0xC0000409`（`STATUS_STACK_BUFFER_OVERRUN`）—— 被 spawn 的那个
node 子进程**崩了**，不是「按约定 `exit 1`」。同一次运行里同一文件的其余 11 条用例
全绿；单独重跑该文件 12/12 绿；紧接着再跑一次全量 `npm run check`（424 条）也全绿。

也就是说：这条失败**不可复现**，但它暴露的不是「偶发噪音」，而是两个真实问题：

1. **「非零退出」这个断言太粗。** 用例的本意是「用法错误必须 exit 1，不能假装成功」，
   断言写的却只是 `code === 1`；失败信息里只有一个裸数字，看不出是崩溃还是脚本自己
   返回了别的码。下次再撞上，读日志的人得自己去查 `0xC0000409` 是什么。
2. **一次全绿不等于稳定。** 在它之前的那次全量运行是绿的，如果当时就此宣布
   「全绿、无优化空间」，这条崩溃永远不会被看见。

## Decision

`tools/archive-note.test.mjs` 的 `run()` 返回值增加 `signal` 字段
（`r.signal ?? null`），并在「缺参数时非零退出」的断言消息里打印它：

```js
assert.equal(r.code, 1, `缺参数必须 exit 1（崩溃不算，signal=${String(r.signal)}），实际 ${r.code}`);
```

断言本身**不放宽**：仍然要求恰好 `exit 1`。崩溃依然算失败 —— 只是现在失败信息
自己说清了它是崩溃。

这条改动不追求「消灭那次崩溃」。崩溃发生在 Windows 上并发 spawn 的 node 子进程里，
没有栈、没有可复现输入，把 `spawnSync` 包一层重试只会把「偶发崩溃」变成
「偶发崩溃但看不见」。**记录 + 让证据可读**是这里能负责的全部。

## Alternatives considered

- **给 `spawnSync` 加自动重试（失败就再跑一次）**：能让这一次的红消失，代价是把
  「子进程会崩」这件事从视野里抹掉。一个在 CI 上偶发崩溃的子进程可能正是某个真实
  资源问题的第一条线索；先抹掉它，等于用绿换掉了信息。这也是本仓库反复拒绝的
  「假绿」形态之一，[故障注入清单必须与磁盘对账](../process/2026-10-21-fault-injection-list-must-reconcile-with-disk.md)
  的 `Note-Skip` 那类口子是同一种错误的轻量版。**这是它最强的理由**：本地验证据此
  变成确定性绿，跑 CI 的人不会再被偶发红打扰。之所以否掉，是因为「偶发红」本身就是
  待查事实，自动重试把它降级成了噪音。
- **直接把断言放宽成 `notEqual(code, 0)`**：能覆盖「崩溃」和「返回 2」两种情形，但那
  正是原用例要防的东西 —— 用法错误必须是一个明确的 `1`，不是随便一个非零值。
  放宽会削弱用例的判定力，换来的只是不再失败。
- **只改日志、不改代码（把 `0xC0000409` 写进笔记了事）**：下次撞上时仍然要靠人去查
  数字含义，且 `run()` 的其余 11 条用例同样看不到 signal。改动只有一行，没有理由不做。

## Consequences

- 收益：失败信息自带「这是崩溃还是脚本自述」的区分；`run()` 的返回值从此带 `signal`，
  后续新增用例可直接用。全量运行的绿不再被当成稳定性的证明 —— 这次崩溃留在记录里，
  而不是被「重跑就绿」消化掉。
- 代价：`run()` 的返回类型多一个字段（`{ code, signal, out }`），JSDoc 已同步；调用点
  不受影响。没有引入重试，所以偶发崩溃**仍会**让 CI 红 —— 这是有意的：宁可见红。
- 仍未覆盖：崩溃的根因未定位（无栈、不可复现），并发 spawn 的 node 子进程在 Windows
  上是否与内存压力/杀软扫描有关，本轮没有证据，不做猜测。
