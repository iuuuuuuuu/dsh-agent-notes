# Agent Note: 双语门禁补上第五项 —— 链接目标逐条比

Status: implemented

> 承接[双语门禁比结构不比字数](../process/2026-10-19-bilingual-docs-compare-structure-not-length.md)
> 与[只比围栏语言标记](../process/2026-10-19-bilingual-only-fence-langs-are-unambiguous.md)。
> 那两篇把「比什么」定到了标题层级 / 代码块 / 表格三层；
> 这一篇补第四层。上游 `up-translation-pairing.ts:368` 的签名有五项，
> 这是最后一项没对上的。

Independent: 不改前两篇的任何判据，只新增一项。

## Problem

本仓库的双语门禁当时比四项：标题层级、代码块数量、围栏语言标记、表格行列数。
**不比链接。**

能抓到的最坏形态是这样：把英文版里那个 GitHub 地址从
`github.com/dhicoc/dsh-better-sidebar` 改成另一个仓库，中文版不动。
标题、代码块、表格、语言标记**全都一致** —— 门禁全绿，而中英读者点过去
是**两个不同的项目**。

这类漂移不是假想：给一个项目改名/迁移时，顺手只改一版是最常见的手滑，
而它恰好落在所有既有判据的盲区里。

## Decision

`structureOf(text, { skipLinkTargets })` 多返回一个 `links`，按文档中出现
顺序排列；`verifyBilingual` 逐条比，先比条数再比值，**只报第一处**。

三条实现判据，每一条都对应一次实测：

1. **必须含绝对 URL。** `markdown-links.mjs` 的 `skippable()` 本来把外链
   全过滤掉了（查断链只管相对路径，那是对的）。为此加了 `includeAbsolute`
   选项，默认 `false` —— 查断链的口径不变。
   ★ 实测依据：真实 README 里两版各 8 条链接，其中 **6 条是外链**。
   只比相对链接等于只比 2 条，把最容易漂的那一类全放了。
2. **语言切换器必须跳过。** 中文版顶部指向 `README.en.md` 的那条、
   英文版顶部指回 `README.md` 的那条，**本来就该不同**。跳过判据与
   `bilingual-links.mjs` 共用 `languageSwitcherTargets()`，不另写一份 ——
   两份口径迟早分叉。实测：不跳过时，真实仓库的两份 README 立刻互相违规
   （各把自己的切换器判成「指错语言」），门禁当场红。
3. **只报第一处。** 链接一旦错位，后面会成串，全报会把根因淹没。

## Consequences

- 用例 22 → 23 条；`bilingual-docs` 的成本没有可测量的变化（多一次正则扫描
  两个 README，两万字符级）。
- 新的误报面：将来若两版**故意**指向不同外链（各自的 issue 页、各自的
  商店页），会被判成漂移。缓解是报错消息直接给出两侧的目标，让人一眼看出
  「这是有意为之，该进跳过名单」「这是手滑」。
- 修复动作仍然只有「让两版一致」一条路 —— 本篇没有加自动改写。

## Alternatives considered

**① 只比相对链接，与 `md-links` 保持同一口径。**
最强理由：仓库里已经有一个「什么算相对链接」的定义，复用它就不会出现
两套口径；而外链在断链门禁里本来就不归它管。

否决理由来自实测：8 条里 6 条是外链，而「改一个项目名只改了一版」恰恰
发生在外链上。为了口径统一而放弃 75% 的覆盖面，是把一致性当成目的。

**② 连锚点（`#安装` / `#install`）一起比。**
否决：跨语言锚点必然不同，这是纯误报。`skippable()` 对纯锚点的跳过
与 `includeAbsolute` 无关，保留。

**③ 不接线，只在笔记里记一笔「上游比了 links」。**
最强理由：当前仓库两版链接完全一致，接上去看不到任何即时收益。

否决理由：这正是[上一轮结论](../process/2026-10-19-upstream-comparison-complete.md)
里说的那种「能吸收但不吸收」的残项。零误报（先量过：8/8 逐索引一致）、
实现与测试合计不到 60 行，没有理由留到下一轮。

**④ 给两版维护一份「允许不同」的白名单。**
否决：白名单会变成另一件必须同步维护的东西，而它漂移时同样没人发现 ——
与[代码块内容比对被否](../../rejected/architecture/2026-10-19-code-block-parity-two-approaches-failed.md)是同一个理由。
